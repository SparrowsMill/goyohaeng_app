# 고요행 User Flow Reference

Source: "고요행 user page content diagram" (Canva whiteboard, PDF export 2026-08-26).
Admin(사장님) 다이어그램은 현재 범위에서 제외 — user 쪽만 반영함.

Use this doc when wiring routes/navigation. `CLAUDE.md` covers *how* to build a
screen (design tokens); this doc covers *what* screens exist and how they connect.

Legend: `<페이지명>` = a screen. `— trigger →` = a button/tap that navigates.

## 1. Entry / Auth

- **Start** → Decision: **로그인 전적이 있는가?**
  - **YES (자동로그인)** → 로그인 성공 → `<본인 방앗간>` (메인 대시보드)
  - **NO** → `<로그인 페이지>`
    - 아이디/비밀번호 입력, "확인" 버튼. 확인 버튼 밑에 "아직 회원이 아니신가요? 회원가입" 버튼.
    - 확인 성공 → 로그인 성공 → `<본인 방앗간>`
    - **회원가입 클릭 →** `<회원가입 페이지>`
      - 이름/생년월일/성별(옵션)/전화번호/이메일 입력 → 아이디(중복 체크)·비밀번호 설정 → 계정 생성 완료
      - **계정 생성 완료 →** `<본인 방앗간>`

## 2. 본인 방앗간 (Main Dashboard)

`<본인 방앗간>` — 빠른 overview + 메인 navigation 역할의 대시보드.
**참새 / 본인 음식 보기 / 맵** 네비게이션이 항상 떠있음.

- **참새 클릭 →** `<참새>` (프로필)
- **본인 음식 보기 클릭 →** `<본인 음식 보기>`
- **맵 클릭 →** `<맵>`

## 3. 참새 (Profile) & Account

`<참새>` — 본인 페이지. 참새 캐릭터, 사용자 이름, 활동 요약(방문 장소 수, 방문 인증
횟수, 완성한 음식 수) 제공. 계정 센터·기록용 플랫폼으로의 연결 지점.

- **완성한 음식 수 클릭 →** `<음식 도감>` (§4)
- **계정 센터 →** `<계정 센터>`
  - 프로필 / 계정 정보 / 설정 / 로그아웃 관리
  - **프로필 →** `<계정 센터에 포함>` — 이름·생년월일·성별(선택) 수정
  - **계정 정보 →** `<계정 센터에 포함>` — 아이디 확인, 비밀번호 변경, 회원 탈퇴
  - **로그아웃 →** End (로그인 페이지로)
- **기록 플랫폼 →** `<기록 플랫폼>` (§7)

## 4. 본인 음식 보기 (My Food)

`<본인 음식 보기>` — 지금까지 만든 음식을 보고 새 음식을 만들러 갈 수 있는 페이지.

- **음식 도감 보기 →** `<음식 도감>`
  - 만든 음식 + 만들 수 있는 음식을 도감 형태로 제공. 이미 만든 음식 / 곧 만들 수 있는
    음식 / 아직 만들지 못한 음식으로 구분. 지역별로 묶어보는 view 옵션 있음.
    이미 만든 음식은 이름+일러스트, 미제작 음식은 이름+실루엣.
  - **이미 만든 음식 클릭 →** `<음식 히스토리>` — 만든 날짜, 획득 일러스트, 사용된
    특별 재료를 얻은 관광스팟 정보
  - **아직 안만든 음식 클릭 →** `<음식 정보>`
    - 필요 재료 리스트 + 보유/필요 수량 표기. 부족한 재료는 획득 가능 장소 추천.
      모든 재료 구비 시 "만들기" 버튼 활성화.
    - **"만들기" 버튼 클릭 →** `<셰프의 주방>`
- **재료 가방으로 →** `<재료 가방>` (§5)

`<셰프의 주방>` — 음식 이름·소모 재료 표시 → 제작 애니메이션 → 완성 일러스트 제공.
기록용 플랫폼 공유 버튼 + "확인"(아무 것도 안 함) 옵션.

- **기록용 플랫폼에 공유 →** `<기록용 플랫폼에 공유>` (§7)

## 5. 재료 가방 (Ingredient Bag)

`<재료 가방>` — 모은 재료 확인. 기본 재료/지역별 재료로 구분. 미획득 재료는 실루엣+이름,
획득 재료는 보유 개수 표시. 우측에 보유 재료로 만들 수 있는 음식 추천 코너.

- **추천 음식 클릭 →** `<음식 정보>` (§4)
- **재료 클릭 →** `<재료 상세 페이지>`
  - 재료 이름, 보유 개수, 재료 특성(예: 제주 특산 재료), 사용되는 음식, 획득 가능 장소 표시
  - **사용되는 음식 클릭 →** `<음식 정보>` (§4, 추정 — 원본에 명시적 도착 노드는 없으나
    문맥상 해당 음식의 정보 페이지로 연결)
  - **획득 가능한 장소 클릭 →** `<장소 정보 페이지>` (§6, 추정)
- **추천 장소 클릭** (재료 미획득 시) **→** `<장소 정보 페이지>` (§6, 추정)

## 6. 맵 → 지역 → 랭킹 → 장소 → 방문 인증

`<맵>` — 지역별 선택 제공. 각 지역은 평균 갭지수에 따라 차등 색깔로 구획. 지역명 크게 +
평균 갭지수 + 관광 스팟 개수 표시. 우측 상단 색상범례 + **"갭지수란?"** 버튼.

- **지역 클릭 →** `<지역별 맵 페이지>`
- **갭지수란? 클릭 →** `<갭지수 설명 페이지>` (팝업, §6-끝)

`<지역 페이지>` — 해당 지역 관광 스팟 조명. 상단에 지역명·스팟 개수·평균 갭지수. 갭지수에
따라 차등 색깔로 지역 지도 위에 표시. 상단 **"랭킹"** 버튼.

- **랭킹 버튼 클릭 →** `<지역별 랭킹 페이지>`
- **맵 지역 하나 클릭 →** `<세부 지역별 랭킹 페이지>`
- **관광스팟 클릭 →** `<장소 정보 페이지>`
- **갭지수란? 클릭 →** `<갭지수 설명 페이지>`

`<지역 랭킹 페이지>` — 지역 내 관광스팟 랭킹. 카테고리(전체/식당/카페/액티비티) + 갭지수
오름/내림차순 선택(기본: 전체·내림차순, 설정값은 다음 방문 시에도 유지). 표시 컬럼:
순위-장소명-카테고리-갭지수-방문인증가능여부-획득가능한재료-영업여부.

- **관광스팟 클릭 →** `<장소 정보 페이지>`
- **갭지수란? 클릭 →** `<갭지수 설명 페이지>`

`<장소 정보 페이지>` — 미방문/방문 인증 완료 상태 표시. 장소 이름, 갭지수 + 간략 설명
(예: "온라인 관심에 비해 실제 방문이 적은 편이에요"), 카테고리, 주소, 운영시간, 주인
소개, 트렌드 요약(전화번호/공식 홈페이지는 옵션). 트렌드 요약은 최다 언급 키워드 3-5개를
클릭 가능한 버튼으로 나열. 소개 바로 밑에 큰 **"방문 인증"** 버튼(옆에 획득 재료 +
매장 자체 방문 혜택 표시). 작은 **"길찾기"** 버튼.

- **트렌드 요약(키워드) 클릭 →** `<트렌드요약 페이지>`
- **길찾기 클릭 →** 외부 지도앱으로 이동 (End)
- **방문 인증 버튼 클릭 →** Decision: **현재 해당 장소의 방문 인증이 가능한 상태인가?**
  (admin 쪽 방문인증 ON/OFF 토글에 의존 — admin diagram 참고, 이 문서 범위 밖)
  - **NO →** `<방문 불가>` — "해당 장소는 현재 방문이 가능하지 않아요. 다른 장소를
    찾아볼까요?" + 비슷한 트렌드의 주변 장소 추천
    - **추천 장소 클릭 →** 다른 `<장소 정보 페이지>`
  - **YES →** `<방문 인증 페이지>`

`<트렌트 요약 페이지>` — 트렌드 요약의 근거가 된 타 플랫폼 게시글. 상단에 주요
키워드 + AI 요약 관심 포인트. 네이버 블로그 링크, 검색어 트렌드 기반 키워드, 타 SNS 검색
링크 제공. 한 장소당 최초 1회 확인 시 기본 재료 1개 지급.

- **(각 외부) 링크 클릭 →** 해당 링크의 외부 사이트로 이동 (End)

`<방문 인증 페이지>` — 방문 인증 혜택(n% 할인, 서비스 제공 등) + 획득 가능 재료 표시.
도착 예정 시간(10분/30분/1시간 이내) 설정 후 **"갈 준비 완료!"** 버튼.

- **갈 준비 완료 버튼 클릭 →** `<방문 인증 확인 페이지>`
  - 장소 이름 밑에 랜덤 6자리 숫자 크게 표시, 작게 주소 표시. 방문 혜택 + 획득 재료 +
    남은 시간 표시. 이 화면을 매장 직원에게 보여주면 직원이 admin 쪽에서 인증번호 확인.
  - **방문 인증 성공 →** `<방문 인증 보상 페이지>`
  - **방문 인증 실패**(설정 시간 초과) **→** `<방문 인증 실패>`

`<방문 인증 보상 페이지>` — 방앗간 재료 사진 + 귀여운 일러스트. 해당 재료로 만들 수 있는
음식 추천. 기록용 플랫폼 공유 버튼 + "확인"(아무 것도 안 함) 옵션.

- **추천 음식 클릭 →** `<음식 정보>` (§4)
- **기록용 플랫폼에 공유 →** `<기록용 플랫폼에 공유>` (§7)

`<방문 인증 실패>` — 시간 초과 시 도달. 슬퍼하는 참새 일러스트. **"다시 도전"** /
**"뒤로 가기"** 버튼.

- **다시 도전 클릭 →** `<방문 인증 페이지>` (재추정)
- **뒤로 가기 클릭 →** `<장소 정보 페이지>` (재추정)

`<갭지수 설명 페이지>` (팝업) — 갭지수 정의 + 산출 공식. "갭지수가 높을수록 알려져
있지만 방문이 적은 곳" 설명 + 갭지수별 색상범례.

## 7. 공유 (Share)

두 곳(방문 인증 보상 페이지, 셰프의 주방)에서 공통으로 쓰이는 공유 플로우.
(SNS 공유는 2026-09-13 결정으로 제거됨 — 기록용 플랫폼 공유만 남음.)

`<기록용 플랫폼에 공유>` — 앱 내 자체 기록 플랫폼 글쓰기 화면으로 이동, 일러스트 자동
첨부. → `<기록 플랫폼 글쓰기>` (§8)로 연결.

## 8. 기록 플랫폼 (Record Feed)

`<기록 플랫폼>` — 최근순으로 날짜별 기록 표시. 글 클릭 시 수정 가능.

- **연필모양(글쓰기) 클릭 →** `<기록 플랫폼 글쓰기>`

`<기록 플랫폼 글쓰기>` — 날짜·장소 설정, 제목(50자 이내), 짧은 글(200자 이내), 갤러리
사진 최대 5개 첨부. "기록용 플랫폼에 공유"를 통해 진입한 경우 날짜/장소/획득 일러스트가
자동으로 첨부된 채 진입.

## Open Questions / Assumptions

원본이 하나의 큰 Canva 다이어그램이라 일부 화살표는 좌표 기반이라 완전히 선형화되지
않았습니다. 아래는 문맥으로 추정한 연결이며, 실제 구현 전에 확인 권장:

- 재료 상세 페이지의 "사용되는 음식 클릭" / "획득 가능한 장소 클릭"의 정확한 도착 화면
- 방문 인증 실패 페이지의 "다시 도전" / "뒤로 가기"의 정확한 도착 화면
- 재료 가방 → "추천 장소 클릭"의 도착 화면
